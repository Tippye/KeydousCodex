从 windows/ 使用已准备的 Python 环境执行：

```powershell
python -m unittest discover -s tests -v
node tests/test_web_state.js
python Verify-Package.py
```

Verify-Package.py 需要先 Build.ps1，且没有另一份桥接程序运行。RGB 实机复验是显式操作：`python Verify-NJ98.py --rgb --data-dir data`，会临时写入工作颜色并在 finally 中恢复原设置。测试失败时应保留恢复记录并检查原因。

## Mac 源码验证范围

- `macos/build/report_state_tests.exe` 和 `keyboard_teardown_state_tests.exe` 均在 Windows/MSVC 编译并由根代理运行，退出码 0。覆盖多页按键状态、引用计数、释放和“失去 readiness 不等于设备销毁”的生命周期回归；不覆盖实际 DriverKit 通信。
- 四个 shell 构建/装配脚本通过 Bash 语法检查；Windows EXE 的构建成功不能作为 Mac 构建证据。
- 原生输入目前仅针对 ANSI NJ98 USB。物理 Caps Lock 指示灯同步尚未实现；不兼容的共享 VirtualHIDDevice 驱动会明确报错，程序不自动替换或移除其他应用共享的驱动。
- 尚需真实 Mac 上构建、签名、公证、系统权限、官方 IoT 连通性、普通/媒体键透传、Fn/Globe、睡眠唤醒、断线和退出释放验收。Mac 完整功能交付状态为待验证，整体任务不能按双平台全部通过关闭。
